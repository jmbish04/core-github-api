# Baton Schema — Stitch Build Loop Communication Protocol

> **Purpose:** Defines the frontmatter contract and handoff rules for the Stitch iterative build loop. Each screen generated by Stitch must comply with this schema to ensure consistent output paths, design enforcement, and loop continuation.

---

## 1. Frontmatter Contract

Every Stitch prompt and output file MUST include the following frontmatter block:

```yaml
---
# OUTPUT
output_path: frontend/src/pages/learning/{view}.astro   # One .astro file per view
component_output_path: frontend/src/components/learning/{ComponentName}.tsx

# DESIGN SYSTEM
design_system: brutalist-sanctuary
design_language: the-monolith

# SURFACE RULES (enforced — no exceptions)
surface_rules:
  no_borders: true                   # ZERO border/divide/ring classes
  color_space: oklch
  zinc_palette:
    page_background: zinc-950        # bg-zinc-950 on outermost layout
    card_surface: zinc-900           # bg-zinc-900 on cards, panels
    elevated_surface: zinc-800       # bg-zinc-800 on hover/active/code
    text_primary: zinc-50            # text-zinc-50 headings and data
    text_secondary: zinc-400         # text-zinc-400 labels and timestamps
    text_metric: zinc-200            # text-zinc-200 + font-mono on all numbers
  chart_label_fill: "#fafafa"        # ALL Recharts axis/tooltip/legend text
  typography:
    headings: tracking-tighter
    metrics: font-mono
  status_colors:
    success: emerald-400
    warning: amber-400
    danger: red-400

# COMPONENT LIBRARY
component_library: shadcn-dark       # Shadcn UI, dark variant only
chart_library: recharts              # Recharts for all data visualization
icon_library: lucide-react

# LAYOUT REQUIREMENTS
layout:
  sidebar: AppSidebar                # MANDATORY on every page; import from frontend/src/components/layout/
  error_wrapper: UnifiedErrorDisplay # MANDATORY on all async data sections
  viewports: [1440x900, 390x844]    # Desktop and mobile both required

# FORBIDDEN
forbidden:
  - "@vercel/ai"                     # Use Workers AI via API routes instead
  - "ai" (Vercel AI SDK)
  - border                           # CSS class
  - border-zinc-*                    # CSS class
  - divide-*                         # CSS class
  - ring-*                           # CSS class (use bg-zinc depth instead)
  - Tabs                             # Multi-tab components; use separate routes

# LOOP CONTROL
loop_checkpoint: .stitch/next-prompt.md   # Write continuation instructions here after EACH screen
loop_version: 2
---
```

---

## 2. Baton Rules

### Rule 1: One File Per View
Each Stitch invocation targets exactly one `.astro` page file and its associated React component(s). Never generate multiple views in a single pass.

```
✅ Correct: Generate dashboard.astro + InsightTrendChart.tsx + PatternDistributionChart.tsx
❌ Wrong:   Generate dashboard.astro + insights.astro in one prompt
```

### Rule 2: Loop Checkpoint is Mandatory
After EVERY Stitch screen generation, the agent MUST write the next iteration's prompt to `.stitch/next-prompt.md`. This is the baton — the next agent run picks it up automatically.

```markdown
# .stitch/next-prompt.md

## Completed in Last Run
- dashboard.astro ✅
- InsightTrendChart.tsx ✅
- PatternDistributionChart.tsx ✅

## Next: Insight Ledger
Generate `frontend/src/pages/learning/insights.astro` with:
- InsightGrid.tsx component (responsive CSS grid)
- InsightCard.tsx (severity badge, prior-fix count, CTA)
- Filter bar: patternType, severity slider, status toggle
- Pagination: 20 per page
- API: GET /api/learning/insights

Apply baton-schema.md frontmatter. No borders. Zinc-950 background.
```

### Rule 3: Verify Before Passing
Before writing `.stitch/next-prompt.md`, verify the generated file:
1. No `border`, `divide-*`, or `ring-*` classes present
2. `AppSidebar` is imported and rendered
3. `UnifiedErrorDisplay` wraps the async data section
4. All Recharts label props include `fill="#fafafa"`
5. Page background is `bg-zinc-950`

If any check fails → fix inline before passing the baton.

---

## 3. View Sequence (Build Order)

```
Pass 1: dashboard.astro          ← Start here; establishes layout pattern
Pass 2: insights.astro           ← Insight Ledger; filter + grid pattern
Pass 3: sessions.astro           ← Audit Log; Shadcn Table + collapsible
Pass 4: babysitter.astro         ← Babysitter HUD; live polling + override
Pass 5: showcase.astro           ← Gallery; static content + CTA
```

Each pass reads the previous `.stitch/next-prompt.md` checkpoint before beginning.

---

## 4. Component Naming Conventions

| Pattern | Example |
|---------|---------|
| View-specific components | `InsightCard.tsx`, `SessionRow.tsx`, `BabysitterSessionCard.tsx` |
| Chart components | `InsightTrendChart.tsx`, `PatternDistributionChart.tsx` |
| Grid/list wrappers | `InsightGrid.tsx` |
| Shared layout | `AppSidebar.tsx` (do NOT recreate; import from `frontend/src/components/layout/`) |

## 5. API Contract for Each View

| View File | API Endpoints | Method |
|-----------|-------------|--------|
| `dashboard.astro` | `/api/learning/insights/global`, `/health/learning` | GET |
| `insights.astro` | `/api/learning/insights` | GET (with query params) |
| `sessions.astro` | `/api/learning/sessions` | GET |
| `babysitter.astro` | `/api/sentinel/status`, `/api/learning/upscale` | GET, POST |
| `showcase.astro` | `/api/learning/insights/global`, `/api/learning/upscale` | GET, POST |

All API calls use `fetch()` with the base URL from `import.meta.env.PUBLIC_API_URL`. No direct D1 access from frontend.

## 6. Recharts Color Enforcement

All Recharts configurations MUST follow this pattern:

```tsx
// ✅ Correct
<AreaChart data={data}>
  <CartesianGrid strokeDasharray="3 3" stroke="#3f3f46" />  {/* zinc-700 */}
  <XAxis dataKey="date" tick={{ fill: '#fafafa' }} axisLine={{ stroke: '#52525b' }} />
  <YAxis tick={{ fill: '#fafafa' }} axisLine={{ stroke: '#52525b' }} />
  <Tooltip
    contentStyle={{ backgroundColor: '#18181b', border: 'none', borderRadius: '4px' }}
    labelStyle={{ color: '#fafafa' }}
    itemStyle={{ color: '#e4e4e7' }}
  />
  <Legend wrapperStyle={{ color: '#fafafa' }} />
  <Area type="monotone" dataKey="count" stroke="#a1a1aa" fill="#3f3f46" />
</AreaChart>

// ❌ Wrong: missing fill on tick, or using border in contentStyle
```
